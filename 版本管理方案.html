DSH AnyApp 的应用、引擎和作品分开管理。发布不是替换一个 APK 就结束：要让用户知道改了什么、能否升级、升级后能否继续工作。

现状与本次范围

0.10.11 已有检查器、24 小时检查节流、断点续传、SHA-256 校验和系统安装器；但独立更新地址未配置，AnyApp 设置页的检测入口因此没有启用。旧自动检查控件挂在旧首页，不能视为已接入 AnyApp 首页。当前可通过下载安装包覆盖升级。

上游 GitHub 自动回退已关闭。还需修正「更新清单指向 GitHub 文件、但下载候选被空镜像列表过滤」的兼容问题，不能只填一个地址就宣布自动更新可用。

用户会如何更新

设置 → 关于与更新 → 查看更新内容与大小 → 下载（可暂停、续传） → 完整性与签名校验 → 系统确认安装 → 回到原来的作品
  • 进入首页并空闲后静默检查，每 24 小时最多一次；失败至少间隔 4 小时重试。离线显示「暂时无法检查」，不误报「已是最新版」。
  • 有新版时用设置角标和轻量卡片提示，提供「稍后」「跳过这一版」；不覆盖键盘，不打断 Creator 生成或手机任务。
  • 点击下载前显示版本、大小、变化、需要的空闲空间；移动网络下载先提示。下载失败保留旧版和可续传文件。
  • 用户确认后调用 Android 安装界面。若有任务运行，先保存并等待完成；不能静默停止任务，也不能自动点击系统授权。
  • 重开时核对实际版本，再显示「更新完成」。系统取消、签名不符、空间不足分别给出可操作提示。

版本规则

层级规则如何保护已有内容
应用用户版本用 0.10.12、0.11.0；Android 构建号严格递增，从已发布最大值继续。同包名、同签名覆盖安装；不卸载、不清数据。签名私钥离线备份，不提交仓库。
稳定 / 测试普通用户只接收稳定版；测试者主动加入预览。独立新用户测试包 app.dshwish.fresh 使用自己的更新清单。禁止正式包与独立测试包串包。每个包名单独校验签名、平台和版本码。
DSH 引擎 / 桥先随 APK 固定版本与桥协议；稳定后再评估独立下载。不得在任务运行中自动重启。启动健康检查；迁移先备份元数据，保留旧字段与回退路径。
作品作品 ID、作者、来源版本、代码哈希及数据结构版本独立记录。预装变化只影响新安装。用户改过的代码不自动覆盖；提供「另存新版」或明确的版本切换。原有名称、图标、授权和记录仍归原作品。

发布和分发

GitHub Release 作为正式版本档案；国内固定下载页作为镜像。每次发布都配套 APK、源码、SHA256SUMS、更新说明和版本清单。文件路径包含版本，已发布的文件不原地覆盖。Gofile 只用于临时分享，不作为长期更新源。

  1. 从明确的源码提交构建 → 自动检查 → 生成候选包与哈希。
  2. 分别验收新用户安装、老用户覆盖升级、导入作品续作、后台提醒与无障碍状态。
  3. 创建草稿 Release，上传全部文件，重新下载核验。最终发布后再原子切换稳定版清单，避免用户读到半套资源。
  4. 稳定清单与测试清单分开；后续增加 10% → 50% → 100% 灰度，失败率异常立即暂停推送。

清单至少包含：产品、包名、渠道、版本名、版本码、最低系统、ABI、包大小、SHA-256、签名指纹、下载地址、发布时间、更新说明及桥协议兼容范围。仅允许 HTTPS 和维护者配置的下载域名；后续为清单加独立签名与防重放版本号。当前 v1 解析器需要先扩展和测试这些字段。

失败时怎么恢复

  • 下载与校验失败：保留当前应用，允许重试和切换已验证来源。
  • APK 出现回归：撤下更新提示，发布更高构建号的修复包。Android 会阻止普通降级，不能把「安装旧 APK」当作通用回滚。
  • 作品新版失败：恢复上一个代码快照；涉及数据结构变化时必须有向后兼容迁移。不能宣称仅回滚代码就能恢复所有新数据格式。
  • 数据导出和备份留在用户控制下，不上传账号、对话和健康记录到版本服务器。

实施顺序

阶段交付与验收
本次 0.10.11发布包、源码、致谢、哈希与安装说明；明确自动更新暂未接通。
下一版优先接 AnyApp 自有清单；修复 GitHub 直链候选；接入新首页；补包名 / 渠道 / 版本码过滤；设置页升级体验。真机用 N → N+1 完成下载、取消、重试、签名拒绝和保留数据测试。
之后灰度与撤回、清单签名、可选增量包；增量只在旧包哈希完全一致时使用，失败回退完整 APK。作品更新作为独立功能验证，避免扩大这次发布风险。
