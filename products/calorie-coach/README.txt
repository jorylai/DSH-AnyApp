热量教练 1.1.0 · 连续对话与本机记忆

这份源码基于用户明确授权导出的热量教练代码，不包含原作品的账号、聊天、独立记录或健康默认值。legacy/ 是纯代码基线；review-runtime/ 的数据为独立演示数据，不进入安装包。

构建：node products/calorie-coach/build.mjs
结果：package/ 和 calorie-coach-1.1.0.anyapp、update.json。应用发布资源从生成结果复制到 app/assets/presets/calorie.anyapp 与 calorie-update.json。

兼容规则
- 作品 ID、profile、会话、用户名称与图标不改变。
- records 继续按 v3 读取。修改时只把用户实际改过的字段合并到原始文档，保留未知字段、长文本与不在当前视图里的旧行。
- 首次写入前，原记录备份到 recordsV3Backup。原备份已经存在则不覆盖；格式不兼容或备份失败会阻止替换记录。
- 写入串行执行，只有宿主确认 saved:true 才提示成功。容量接近上限时明确报错，不再自动裁掉早期历史。
- 老建议保留在原数据里，点开继续聊会创建关联对话，不把 AI 建议当成用户事实。

新记忆存储
- coachCatalog：会话索引、标题、分页指针和状态。
- ccP…：按宿主 41 字符集合名规则生成的消息分片；每片小于380KB，先写不可变分片，再提交索引。中断写入不改变已提交对话。
- coachMemory：结构化偏好、限制、目标、习惯、背景，来源、用户原话、状态与日期；以及已忘记的消息标记。
- coachDraft：本机草稿。
- 数据都在本作品 namespace 中，不另设账号或服务器。AI 仍使用当前宿主已登录模型；用户发送时会将所需上下文交给模型处理。

提取和引用
模型一次返回回复和最多4个记忆候选。保存前校验来源确实是本次用户消息，证据逐字出现在原话中。拒绝凭据、AI自己提出的建议、捏造文本和明显临时状态。冲突的新目标先进入待确认，不静默覆盖旧目标。相关记忆按关键词和类别检索，再和本机资料、近7天记录及最近20条对话一起构成下一次上下文；完整历史仍留在本机分片中。
可以修改、忘记、暂停记忆和导出对话与记忆。忘记会从记忆库移除事实，并在以后给模型的上下文中屏蔽原消息；原始对话仍可回看。手动纠正过的记忆仍保留来源关联，忘记时同样屏蔽来源。

代码升级
仅在现有 client 与已核实基线完全匹配时自动升级；自行改过的代码不被覆盖。先建代码快照，核对预期源 hash，事务替换代码后安装。安装失败恢复旧快照。更新只触及代码文件，不读写记录目录。运行中的 Creator 会话不会被静默重启。

验证
Node 数据/兼容/升级测试、真实 React 组件浏览器测试，以及宿主旧发布/安装回归共同验证。浏览器模型是本机模拟器，不代表真实登录模型或真机已完成验证。手机被用户拿走后没有继续设备操作，最终真机安装、实际模型回答和 Android 键盘仍待补验。
